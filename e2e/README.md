# Detox E2E suite

Five end-to-end flows that drive the DevWallet app against a real iOS simulator
or Android emulator.

## Mock layer (E2E.3 / E2E.4)

The Faucet + Webhook flows depend on a backend + WebSocket. For E2E they run
against in-memory mocks instead, selected by a **build-time env flag** — no
native module, no per-launch arg:

- `.env.e2e` (gitignored, generated by copying `.env`) adds `E2E_MOCK=1`.
- `.detoxrc.js` build commands prefix `ENVFILE=.env.e2e`, so `react-native-config`
  bakes `E2E_MOCK=1` into the Detox binary.
- `src/core/di/container.ts` swaps `FaucetRepositoryImpl` → `MockFaucetRepository`
  and `WebhookRepositoryImpl` → `MockWebhookRepository` only when
  `Config.E2E_MOCK === "1"`. Normal `.env` builds use the real repos.
- The mocks (`src/repositories/mock-*.repository.ts`) return canned data and
  push canned `faucet.success` / `webhook.event` events through their `events$`.

Regenerate `.env.e2e` after changing `.env`:

```bash
cp .env .env.e2e && printf '\nE2E_MOCK=1\n' >> .env.e2e
```

The onboard + RPC specs don't touch those repos, so they pass on the same build.

## Real send (E2E.2)

`send.spec.ts` is the one flow that signs + broadcasts for real on Sepolia. It
needs a dedicated **testnet** wallet funded with a little Sepolia ETH, supplied
out of source so no key is committed:

```bash
cp e2e/secrets.env.example e2e/secrets.env   # gitignored
# edit e2e/secrets.env → set E2E_SEND_MNEMONIC (12/24 words), optional E2E_SEND_TO
bun run e2e:test:ios   e2e/send.spec.ts       # Metro must be running
```

- The mnemonic is read by the **Node** test runner (`e2e/load-secrets.js`,
  loaded via the e2e jest `setupFiles`) and typed into the restore screen — it
  never enters the app binary or the repo.
- Without `e2e/secrets.env`, the spec `describe.skip`s, so CI stays green.
- The spec runs fine on the E2E (mock) build — the Faucet/Webhook mocks don't
  touch the Send path. It blocks every chain host **except** `1rpc.io/sepolia`
  so the Dashboard's background refresh can't stall Detox on slow testnets.
- **Heads-up:** `1rpc.io/sepolia` (the app's Sepolia RPC) rate-limits its free
  tier — a broadcast can fail with "usage limit for your current plan". If that
  happens, re-run, or point the app at a dedicated Sepolia RPC. The nav + form +
  signing path are verified; only the final on-chain confirmation depends on a
  funded wallet + a non-throttled RPC moment.

## Permission popups (auto-Allow)

No manual tapping of OS dialogs:

- **iOS:** every `device.launchApp(...)` passes `permissions: { notifications: "YES" }`
  so the notification dialog is pre-granted.
- **Android:** `launchApp` permissions are iOS-only, so `PushService.ensureAuthorized`
  short-circuits (returns authorized without prompting) when `E2E_MOCK === "1"`.

`App.tsx` also calls `LogBox.ignoreAllLogs()` under `E2E_MOCK` — the dev warning
toast renders a bar over the bottom tab bar that fails Detox's 100% visibility
check on tab taps.

## Run gotchas learned during bring-up

- iOS **debug** builds need Metro running (`bun start`). Without it the app shows
  a red "No script URL provided" box and every matcher fails.
- Use `toExist()` (not `toBeVisible()`) to gate screen-presence — full-screen
  root `<View>`s can fail Detox's 75% visibility threshold even when on top.
- Tap bottom-tab buttons with `tapAtPoint({ x: 30, y: 25 })` — a plain `.tap()`
  can fail the visibility check on the tab bar.
- Dismiss the keyboard before tapping a button that sits below it (a tap landing
  on the keyboard is a silent no-op) — e.g. tap a chip first.

## One-time native patches

### iOS — already done

Detox 20.51 ships a prebuilt XCUITest bundle (`Detox-ios-xcuitest.tbz`) inside
`node_modules/detox/` and installs it into the simulator at test time. **No
Podfile, AppDelegate, or xcodeproj edits are required.** Just run `pod install`
if you haven't already, then `bun run e2e:build:ios`.

### Android — already patched (landed in this branch)

The following Detox patches are committed:

- `android/app/build.gradle` — `testBuildType = "debug"`, `testInstrumentationRunner = "androidx.test.runner.AndroidJUnitRunner"`, `androidTestImplementation("com.wix:detox:+")` + `androidx.test.ext:junit`, plus a local Maven `repositories { maven { url("${rootDir}/../node_modules/detox/Detox-android") } }` block since Detox's AAR is published as a flat repo inside `node_modules`, not Maven Central.
- `android/app/src/androidTest/java/com/devwallet/app/DetoxTest.kt` — single `@RunWith(AndroidJUnit4)` entry that bootstraps `Detox.runTests(...)` against `MainActivity`.
- `android/app/proguard-rules.pro` — keep rules for `com.wix.detox.**`, hamcrest, junit, and the `DetoxTest` class so Release builds remain instrumentable.

You only need to create an AVD named `pixel_6_api_34` (Android 14, x86_64) via
Android Studio AVD Manager. `.detoxrc.js` references this exact name.

## Required app-side testIDs

Each spec drives the app through `by.id("...")` selectors. Before any spec
turns green you must add the matching `testID` props to the corresponding
screens / components. Grep this folder for `by.id` to get the full list, e.g.:

```bash
grep -rh "by.id" e2e/ | sed -E 's/.*by\.id\("([^"]+)"\).*/\1/' | sort -u
```

## Gotchas observed during bring-up

- **`device.setURLBlacklist([".*"])` must come AFTER `device.launchApp(...)`**
  — calling it before the first launch errors with "Detox can't seem to
  connect to the test app(s)!".
- **Re-launch wipes the blacklist** — after every subsequent
  `device.launchApp({ newInstance: true })` you must call
  `device.setURLBlacklist(...)` again.
- Without the blacklist, Detox's `NetworkIdlingResource` stalls every tap
  until **all** pending RPC fetches resolve. Dashboard mounts 8+ chain
  fetches (mempool.space, 1rpc.io, sepolia.base.org, etc.). On Android
  emulator (SwiftShader software rendering) those can take >60s, busting
  the 90s idle timeout. iOS sim is much faster but a long idle wait is
  still wasteful.
- **Android backend specs** (faucet, webhook) must point
  `API_BASE_URL` at `http://10.0.2.2:3000/...` — Android emulator
  `localhost` resolves to the emulator's own loopback, not the host. iOS
  simulator shares the host loopback so `localhost` works there.

## Test wallet

`fixtures/test-wallet.ts` ships the standard Hardhat dev mnemonic. Send it
0.01 ETH on Sepolia before running `send.spec.ts` — that flow performs a real
broadcast. The faucet + webhook flows instead use the build-time mock layer
(see **Mock layer** above), so they need no funding and no backend.
